# Elevator Inc.

依照 `obsidian/Projects/incremental game ideas.md` 第四節的設計做出來的完整增量遊戲。
純前端、零依賴、零 build step、零伺服器依賴 —— 用任何靜態伺服器打開 `index.html` 就能玩。

```bash
python -m http.server 8131
```

或用專案內建的設定：`.claude/launch.json` 的 `elevator-proto`。

- `index.html` —— 首頁（開始／玩法說明／帳本／更多遊戲）
- `game.html` —— 遊戲本體
- `prototype.html` —— 最早的兩天原型（只有核心動詞：點樓層 → 電梯過去 → 開門 → 收錢），留著當手感基準

介面有**繁體中文與英文**兩種語言，右上角切換，選擇會記在 localStorage。
第一次進來看瀏覽器語言決定。

## 檔案結構

| 檔案 | 負責 |
|---|---|
| `js/content.js` | **所有內容都是資料**：升級、自動化階梯、乘客、樓層帶、技能樹、成就。改平衡只改這裡 |
| `js/state.js` | 單一個可序列化的 `GameState`、衍生數值、成本公式、Prestige、存讀檔、離線收益 |
| `js/sim.js` | 模擬：乘客、電梯運動學、調度演算法、過熱、評價、統計流量模型 |
| `js/render.js` | canvas 繪圖與相機 |
| `js/ui.js` | 六個分頁面板 |
| `js/main.js` | 固定時間步迴圈、輸入、音效 |
| `js/landing.js` | 首頁：說明、帳本（直接讀存檔，不啟動遊戲迴圈） |
| `js/i18n.js` | 語言狀態與 UI 字串字典 |
| `js/i18n-content.js` | content.js 那些資料的英文對照；查不到就退回中文 |

存檔只存 `GameState`（約 700 bytes）。乘客陣列**不進存檔**，重開時重新生成。

## 設計對照

| 設計 | 實作 |
|---|---|
| 4.3 手動調度 | 點樓層叫梯；沒買自動關門前，門會一直開著等你下一次點擊 |
| 4.4 馬達過熱 | 按住 🔥 或空白鍵超速 1.8×，熱量累積、過熱停機 8 秒；超導馬達滿級後移除此機制 |
| 4.5 三種貨幣 | 現金 $ / 藍圖 📐 / 評價 ★（乘數，不是貨幣） |
| 4.6 五個互相牽制的屬性 | 速度、加速、載客、開關門、井數 —— 載客量越大上下客越久，沒有全面更好的選項 |
| 4.8 自動化階梯 | 九階全部實作，而且**真的改變電梯行為**（見下方實測） |
| 4.9 乘客類型 | 12 種 + 圖鑑；13 樓的幽靈、貓、CEO、搬家公司都在 |
| 4.10 樓層類型 | 七個樓層帶，各有租戶等級（票價倍率）與專屬乘客；100 樓（屋頂）開放結局 |
| 4.11 Prestige | 藍圖 = ⌊√(本輪收入 ÷ 1萬)⌋，三大分支技能樹 |
| 4.12 相機拉遠 | 相機永遠框住整棟樓，樓越高塔越細 |
| 4.13 統計流量模型 | **已移除**：100 層全部逐個模擬，收入只有一種來源——真的把人送到。離線收益仍用平均速率直接算 |
| 4.14 風險對策 | 低樓層流量隨大樓高度同步成長；統計頁提供單一「效率」指標；每個演算法配白話說明 |

## 演算法真的有差（實測）

35 樓、3 井、相同升級、各跑 600 秒模擬：

| 調度 | 送達 | 放棄率 | 收入 |
|---|---|---|---|
| FIFO | 65 | 69% | $3.0K |
| SCAN | 102 | 53% | $3.8K |
| LOOK | 112 | 48% | $4.5K |
| + 目的地控制 | 102 | 52% | $4.8K |
| + 群組控制 | 138 | 36% | $6.6K |
| + 快車 + 雙層轎廂 | 179 | 18% | $9.1K |

LOOK 對 SCAN 的優勢**跟樓高有關**：10 樓時兩者幾乎沒差（空段很短），35 樓才拉開。
遊戲內的統計頁看得出每一座井的效率，也看得出哪一座在偷懶。

## 除錯鉤子

`window.__dbg` 提供 `cash() / bp() / floors() / fast(秒) / buyUp() / buyAuto() / tap() / reset()`，
用來跑平衡測試。正常遊玩不會碰到。

## 平衡現況

開場是 **5 層樓 + $200**——剛好買不起「自動關門 $60 + 加蓋 $150」兩樣，第一個決定就是選一個。
第一次加蓋是把整棟樓**加倍**（5 → 10 層），不是 +50%。

自動玩家（貪心買法）跑出來的曲線，五次取樣：自動關門 1 分（五次都是）、
加倍到 10 樓 3–11 分、收入 $500 約 12 分、FIFO 18–25 分、收入 $1萬 約 41 分、
$10萬 約 61 分、$100萬 約 86 分、蓋滿 100 樓 58–86 分（中位 69）。結局（$20M + 📐20）要靠多輪累積技能樹：機器人買齊藍圖階調度（38 📐）之後，
實測在**第 19 輪第 83 分**達成，當時技能樹 77/83、末段收入約 $4.6k/秒。
真人會慢一些，總長度大致落在設計目標的 4–6 小時。這組數字是機器人跑出來的；2026-09-04 已有第一次真人試玩。
