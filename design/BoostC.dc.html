C ── 踏板

軸：這顆鈕自己承載的狀態 ＝ 一個位元＋一個秒數　·　換來的不是資訊，是位置
動機
它是這個遊戲唯一的動詞，卻跟「回首頁」放在同一個抽屜裡。 C 把它搬到畫布上、拇指構得到、而且看得到它作用的對象——按住的時候火焰就在同一個視野裡。 而且這不是新語彙：`#evac` 已經是一顆浮在畫布上、4px 邊框、`5px 5px 0` 硬陰影的鈕， C 只是把超速做成同一族的第二顆，擺在對角。踏板的形狀本身就在說「按住」。
主要缺點
它是唯一會遮住畫面的方向。量過：96px 寬的踏板在 375 的手機上蓋掉畫布 x 6–102， 而 `fx0 ≈ 37`、樓層號從 `fx0+12` 開始 ——最低那 2～3 層的樓層號整個被壓在踏板底下。 另外 `#toasts` 手機是 `bottom:56px`、`z-index:50`，踏板在 `bottom:70px`； 兩者在距底 70–90px 這一段重疊，而蓋上來的正是「🔥 馬達過熱」那一則。 最後：老玩家會先往頂欄找。

工單第 4 條：過熱那 8 秒怎麼交代
C 只交代一個位元＋一個秒數：有沒有井鎖住、最長的那個還剩幾秒。 鉸鏈那條變 `--bad` 並長出「過熱 5s」，其餘什麼都不畫。 理由是 C 的踏板本來就貼在畫布旁邊——玩家的眼睛已經在那一區， 連續的熱量交給 #144 的火焰長度（那是既有素材，而且它畫在真正會過熱的那一台車上， 不像鈕上的槽只能給一個「最熱的井」的摘要）。

同樣地：踏板不 disable。 `s.lock` 是每座井各自的（`sim.js:1404`），一座鎖住的時候其他井照樣吃 1.8 倍。
遮擋與碰撞 ── 量過的數字
手機 375：`#stage` 有 `padding:0 8px`，畫布 359 寬 → `skyPad = clamp(359×0.085, 14, 62) = 31`，`wall = 6` → `fx0 = 37`，樓層號從 `fx0+12 = 49` 起。 踏板 `left:14px` 寬 96 → 蓋掉畫布 x 6–102，樓層號那一欄整個在裡面。 高度上 `bottom:70px` + 66 高 → 蓋掉街道（`groundH` 上限 22px）再往上約 2–3 層。
桌機 1280：stage 946 寬 → `fx0 = 68`；踏板 `left:20px` → 蓋畫布 x 12–108，同樣壓到樓層號欄， 往上約 2 層。
`#evac` 不打架：桌機它在 `right:360px`（stage 右緣）、手機 `right:14px`，跟踏板是對角； 手機上 96 + 14 + 疏散鈕 ~122 + 14 = 246 < 375。
`#toasts` 會打架：手機 `bottom:56px`、`z-index:50`、寬到 `100vw-24 = 351`， 踏板佔距底 70–136；重疊在距底 70–90，而且蓋上來的正是「🔥 馬達過熱」那一則。 真的要做的話，`#toasts` 在手機要往上讓到 `bottom:142px`，或踏板降到 `bottom:56px` 以下—— 兩個都是 orchestrator 要裁的跨檔案改動。
實作時會動到什麼（選中之後才做）
`game.html`：`#boost` 從 `.btns` 搬出去，放在 `#evac` 旁邊當第二顆浮動鈕。
`css/style.css`：一條新的 `#boost` 規則（照抄 `#evac` 的語彙）＋ 兩支 media query； `#toasts` 的 `bottom` 要重新裁一次。
`js/main.js`：`pointerdown` 綁定不用改（選擇器沒變）；新增鎖住狀態的每幀寫入器（只有一個布林 + 一個整數秒）。
`js/i18n.js`：2–3 支字串 —— writer 的檔案。
`js/render.js`：不動，但畫布左下角從此有東西壓著，`#144` 的火焰不受影響（火在右邊的井上）。
