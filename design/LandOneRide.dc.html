動機

它是唯一一個把「來不及」演出來的方向。9 點 05 分 13 樓一次湧出十幾個人、耐性條由綠轉紅、一台車在門口只吃得下四個——這一段五秒鐘講完了規則書那句「你買的不是自動點擊器，是更好的調度演算法」，而規則書要點進去才看得到。往上爬的相機也把「樓越高人越不一樣」講成一件會發生的事，不是一張對照表：你是經過那幾群人的。

主要缺點

節奏是演出來的——但只剩節奏。什麼時候停、停多久、時鐘牌上的分鐘，這三樣資料裡沒有，是我寫的。其他每一個字都從 EVENTS 生成：事件名、起訖、時段、人數，連隊伍多長都是 (n0+n1)//2。BE 明天把 townhall 的 hours 從 9-11 改成 8-10，committed 的產物跟活的 EVENTS 對不上 → harness 紅（#152 第 26 組）。剩下的代價是它有 18 秒：三秒就離開的訪客只會看到第一站。

18 秒的四站10:05 大廳 1 樓（0.0–2.2s）  →  09:05 辦公 13 樓（4.4–7.6s）  →  22:40 觀景台 79 樓（10.0–13.2s）  →  22:10 實驗樓層 93 樓（15.2–18.0s）
關鍵影格怎麼來的不是手寫百分比：tools/landgen.py 從 B_BEATS 與每一層樓的 y 算出 camera / carUp / carDown / doorL / doorR 五組 @keyframes。改一個時間點，五組一起重算，不會對不上。
reduced-motion五組動畫全部 animation: none，畫面停在 t=0：大廳、門開著、三個人要上車。那一格自己就成立——方向 A 就是這個退路的完整版。
手機 390px這一格是用 scale(0.66) 縮的，而真的首頁沒有這樣做：產品那一份把 <svg> 設成 width: 100% + 外框 aspect-ratio。相機的 translateY 是 viewBox 的 user unit，會跟著自己縮，所以不需要 CSS scale()，shape-rendering: crispEdges 還救得回來。
100 樓那題（#152 待裁決）相機往上爬是「樓越高人越不一樣」最好的表達，但它同時暗示「你會一路蓋到 100 樓」。100 樓是 ENDING_FLOOR，規則書寫得很清楚：那要 $1000 萬加 20 張藍圖，不是第一棟樓就到得了的地方。這份稿現在停在 93 樓（實驗樓層的夜班交接）。裁決如果是「帶到 100 樓」，把 B_BEATS 最後一列換成 (15.2, 18.0, 100, 30, 'boarding') 重新生成就換完了：樓層、相機關鍵影格、字幕全部自動跟上。
要新文案嗎事件名與樓層帶名不用（EVENTS[].name / BANDS[].name，i18n-content.js 中英兩版都有）。真的首頁另外需要六個接合詞的鍵（landRideAt / landRideHours / landRideCount / landRideAllDay / landRideLobby / landRideAlt），已經照 #149 的先例加在 js/i18n.js。
